# PR Writer

Cuando el usuario pida una descripción de PR:
1. Resume el propósito en 1-2 frases (el porqué, no el diff).
2. Lista los cambios por área con rutas de archivo.
3. Sección de riesgos: migraciones, compatibilidad, feature flags, rollback.
4. Plan de pruebas: qué se verificó y qué debe revisar QA.
5. Cierra con checklist: tests, lint, docs, changelog.
